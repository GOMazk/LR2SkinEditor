# AI_1 최신 기능을 AI_2에 이식

## 브랜치와 결과

- 저장소: [GOMazk/LR2SkinEditor](https://github.com/GOMazk/LR2SkinEditor).
- 작업 브랜치: `AI_2`. `AI`와 `AI_1`에는 쓰기 작업을 하지 않았다.
- 시작점: `58f76020438a308e8b3f5b04984e475e35f5f4c3`.
- 읽어 온 AI_1: `1b243bf6c4d1d7c45351b642b462ca3bcc0a6d10`.
- 시작 AI_2가 AI_1의 조상이므로 `git merge --ff-only origin/AI_1`로 8개 커밋을
  가져왔다. 기존 AI_2 기능을 보존하면서 원본 변경 이력도 유지한다.
- 이후 수정은 AI_2 로컬 커밋에만 포함한다. GitHub push/PR/릴리즈는 하지 않았다.

## 가져온 기능

- Object를 sibling CSV로 분리 저장하고 파일별로 탐색/편집한다.
- File Manager의 CSV 폴더 트리와 다중 행 Text Editor를 사용한다.
- 선택 파일만 Preview하거나 여러 파일의 표시를 개별 제어한다.
- Custom Files 편집/후보 선택과 Object·Asset·CSV 편집 화면 전환을 개선한다.
- 재생 뒤 정적 Preview로 복원하고 Timer Control/Customize 도킹을 정리한다.

## 통합 중 수정

| 파일 | 변경과 이유 |
|---|---|
| `winWorkspaceObjectCommands.cpp` | CSV 분리로 추가되는 행에 맞춰 selected/active/anchor를 보정한다. ID 없는 두 Object의 선택, owner, Undo/Redo 회귀 검사를 추가했다. |
| `LR2/structure.h`, `LR2_skinload.cpp`, `LR2_skindraw.cpp`, `skin.h/.cpp` | 보간되는 그리기 순서를 파일 소유권으로 사용하면 다른 파일에 의해 Object가 숨겨진다. 런타임 sourceOrder를 별도로 유지하고 버퍼 할당을 sizeof 기준으로 맞췄다. |
| `winWorkspace.cpp` | 실제 DST/이동 bar 보간과 draw-buffer 증설 검사 추가. x64 스택 초과를 일으키던 큰 테스트 fixture는 heap에서 소유한다. |
| `AGENTS.md`, `AI_COLLABORATION.md`, `ai-context.ps1` | 이전 저장소 주소와 잘못된 AI 대상 안내를 새 저장소/AI_2로 변경하고 브랜치 소유권을 기록했다. |
| `test.ps1` | 자동 테스트 프로세스를 숨겨진 창으로 실행한다. |

CP932 저장, include/IF 소유권, 기존 애니메이션 순서와 OLRskin 0.9 직렬화는 유지한다.
런타임 DSTdraw의 크기는 80→84바이트이며, 소비 코드는 같은 프로젝트에서 소스 빌드된다.

## 실제 검증

- `scripts/ui-map.ps1 -Check`: 18 windows, 14 flows/shells, 783 controls, 오류 0.
- `scripts/docs-check.ps1`: 상대 링크와 Markdown 검사 통과.
- `scripts/build.ps1`: Release Win32 빌드 통과.
- `scripts/build.ps1 -Platform x64`: Release x64 빌드 통과.
- `scripts/test.ps1 -ExecutablePath .build/verified-win32/SkinEditor_DX9.exe`:
  최종 검증 폴더에서 16/16 통과.
- x64 실행 파일의 동일 self-test: 16/16 통과.
- FT 7키·5키 스킨의 작업용 복사본으로 `--skin-reload-smoke`와
  `--skin-multi-workspace-smoke`: 모두 exit 0. 연속 로드, 두 runtime의 재생 진행,
  한쪽 정적 복원과 재시작을 검증했다. 원본 스킨은 수정하지 않았다.
- `scripts/ai-context.ps1 -Check`: 생성 결과의 저장소와 baseline/target을 AI_2로 확인.
- `git diff --check`: 통과.

Preview 회귀는 수정 전 exit 112로 재현했다. 초기 샌드박스 실행에서는 그래픽 검사
4개가 실패했으나 권한을 확장한 실행에서 통과했다. 새 선택 검사는 앱과 같은
Undo/Redo 후 모델 재구성 단계가 필요해 테스트 순서를 보완했다. x64 OLR 검사의
초기 exit `0xC00000FD`는 heap fixture 전환 후 정상 종료했다. 실패 기록도 `.build`에
보관해 최종 성공 기록과 구분한다.

## 산출물과 남은 검증

- 최종 Win32 실행 파일: `.build/verified-win32/SkinEditor_DX9.exe`.
- SHA-256: `1777D1655A2CF74008D3020326E4AF0FFC926EA1C55F997AE4A890C95675393B`.
- 같은 폴더에 D3DX9 runtime과 PDB가 있다. 파일 복사 후 해시와 자체 테스트를 확인했다.
- 저장소가 추적하는 `SkinEditor_DX9/Release`의 원본 exe/pdb는 빌드 전 복사본으로
  복원했다. 위 검증 폴더가 이번 수정이 포함된 실행 파일이다.
- JUnit: `.build/test-results`와 `.build/test-results-x64`.
- 런타임 smoke: `.build/test-results/native-skin-smoke.json`.
- C4244, C4819 등 기존 LR2/DxLib 컴파일 경고는 남아 있다. 경고를 숨기지 않았다.
- 네이티브 GUI의 실제 마우스 조작, 모든 외부 스킨의 시각 비교, 실제 LR2 실행은
  미검증이다. 자동 runtime smoke는 이 수동 검증을 대신하지 않는다.
